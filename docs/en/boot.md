# Boot chain

*[Version française](../fr/boot.md)*

How an unsigned mainline kernel boots on a device whose secure boot is closed, and what to know about
the vendor bootloader.

## Vendor bootloader

- U-Boot **2009.08** (Gigaset build `2009.08.maxwell.gc.014`, 2015) in the **SPI NOR**, not on the eMMC.
- Console on UART2, 115200 8N1. `bootdelay` is 0: press a key while powering on to get the prompt.
- The environment stored in the NOR is invalid on a stock unit (`bad CRC, using default environment`):
  the defaults are used until the first `saveenv`.
- `adb reboot bootloader` enters fastboot (protocol 0.5, USB `18d1:0d02`): only `getvar version`,
  `product` and `serialno` answer, there is no lock state and no `oem` command. `fastboot boot`
  works but goes through HAB (below). Never use `fastboot flash`: it targets the eMMC.

## Secure boot (HAB) is closed

```
HAB Configuration: 0xcc, HAB State: 0x99
```

`0xcc` is `HAB_CFG_CLOSED` and `0x99` is `HAB_STATE_TRUSTED`: the secure boot fuses are blown. The boot
ROM authenticates U-Boot, then U-Boot authenticates the **kernel** of the Android boot image, both on a
normal boot and with `fastboot boot`. An unsigned kernel is refused:

```
Authenticate uImage from DDR location 0x14008000...
HAB Event 1: 0xdb 0x00 0x08 0x41 0x33 0x05 0x0a 0x00
Authentication Failed
```

(status `0x33` HAB_FAILURE, reason `0x05` HAB_INV_IVT: no IVT/CSF after the kernel). Only the kernel is
signed: the ramdisk, the DTB (`second`) and the command line of the boot image are not.

## The way around: `go`

U-Boot's `go <addr>` jumps to an address **without any authentication**. It does not pass a device
tree, an initrd or a command line, and it leaves the CPU in U-Boot's state. The solution has three
parts:

1. **goshim** ([tools/goshim/goshim.S](../../tools/goshim/goshim.S)), a 1 KiB position-independent stub
   placed in front of the zImage. It disables caches, L2 and MMU, builds an ATAG list with
   `ATAG_INITRD2` from the two extra arguments of `go`, and jumps to the zImage with the registers
   Linux expects.
2. The **device tree is appended** to the zImage (`CONFIG_ARM_APPENDED_DTB`), and the decompressor
   merges the ATAGs into it (`CONFIG_ARM_ATAG_DTB_COMPAT`): the initrd location ends up in
   `/chosen/linux,initrd-*`. The command line is `/chosen/bootargs` of the device tree.
3. The kernel package builds `/boot/go.bin` = goshim + zImage + DTB.

```
Boot ROM (HAB closed)
 └─ vendor U-Boot 2009.08 (SPI NOR, signed, untouched)
     └─ bootcmd from the NOR environment (not signed)
         ├─ fatload mmc 1:1 0x12000000 go.bin       goshim + zImage + appended DTB
         ├─ fatload mmc 1:1 0x14000000 initramfs    generated by postmarketOS
         └─ go 0x12000000 0x14000000 ${filesize}
             └─ goshim: caches/MMU off, ATAG_INITRD2, jump to the zImage
                 └─ Linux → postmarketOS initramfs → root filesystem on microSD p2
```

### Memory map

| Address | Content |
|---|---|
| `0x10000100` | ATAGs written by goshim |
| `0x10008000` | decompressed kernel |
| `0x12000000` | `go.bin`: goshim (1 KiB), zImage at `0x12000400`, DTB after it |
| `0x14000000` | initramfs |

## U-Boot environment

The environment set during [installation](install.md#4-make-the-card-boot-automatically):

```
setenv android '<original bootcmd>'
setenv sdgo 'go 0x12000000 0x14000000 ${filesize}'
setenv sdboot 'mmc dev 1 && fatload mmc 1:1 0x12000000 go.bin && fatload mmc 1:1 0x14000000 initramfs && run sdgo'
setenv bootcmd 'run sdboot; run android'
saveenv
```

- The hush shell expands a whole line before running it: `${filesize}` must be in a separate
  variable (`sdgo`), expanded only by `run`, otherwise it would still hold the size of `go.bin`.
- Without a card, or without `go.bin`/`initramfs`, `sdboot` fails and `run android` boots Android.
- A kernel without initramfs can be started with `go 0x12000000` alone.

## microSD constraints

- **MBR only**, partition 1 of a FAT type: U-Boot 2009.08 ignores GPT. pmbootstrap creates a GPT
  with partition 1 typed EFI, so `install-sdcard.sh` converts the image (`sgdisk --gpttombr`, type `0x0C`).
- The boot partition is **FAT32** (`deviceinfo_boot_filesystem="fat32"`). `ext2load` hangs on ext4
  with extents: never use it.
- SDHC up to 32 GB; UHS-I cards may not initialise.
- The controller runs in 3.3 V high-speed mode (~20 MB/s). Random access speed of the card matters
  most for responsiveness.

## Android side (for reference)

- ADB: mini-USB port behind the left cover of the base, developer options → USB debugging.
  `user` build with release keys: no `adb root`.
- Vendor boot image (eMMC p1): kernel at `0x10808000` followed by its IVT and CSF, ramdisk at
  `0x11800000`, DTB as `second` at `0x11700000`.
- Vendor kernel command line: `console=ttymxc1,115200 init=/init video=mxcfb0:dev=ldb,bpp=32 …
  androidboot.hardware=gigaset cma=384M`.
